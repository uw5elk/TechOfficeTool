# TechOfficeTool

Програма для Windows для пакетної роботи з документами Word і фотографіями: конвертує старі `.doc`,
зменшує розмір `.docx` і зображень, перейменовує фото та прибирає з них метадані (EXIF, GPS).

Автор: UW5ELK

## Режими

| # | Режим | Що робить |
|---|-------|-----------|
| 1 | **Конвертувати .doc → .docx** | Пакетно переводить старі документи в сучасний формат. Потрібен Microsoft Word. |
| 2 | **Стиснути зображення в .docx** | Зменшує розмір документів, стискаючи картинки всередині. Текст і верстка не змінюються. |
| 3 | **Стиснути звичайні зображення** | Пакетно зменшує JPG, PNG, GIF, BMP, TIFF, WEBP. |
| 4 | **Перейменувати фото** | Дає файлам назви за шаблоном, з сортуванням за іменем або датою. |
| 5 | **Видалити EXIF** | Прибирає з фото GPS, модель камери, коментарі, XMP/IPTC. |

## Встановлення

**Готовий EXE.** Якщо в розділі [Releases](../../releases) є реліз - завантажте `TechOfficeTool.exe` і запустіть.
Встановлювати нічого не потрібно. Інакше зберіть exe самостійно (див. нижче).

**Через Python** (Windows 10/11, Python 3.9 або новіший з галочкою «Add to PATH»):

1. Завантажте проєкт: **Code → Download ZIP** і розпакуйте.
2. Запустіть `setup_install.bat` - він встановить залежності й створить ярлик на робочому столі.
3. Надалі запускайте ярлик або `Start_Compressor.bat`.

## Як користуватися

1. Оберіть режим і папку з файлами.
2. Для режимів 1-3 оберіть, **куди зберігати**: окрема папка (оригінали лишаються як були) або «в ту саму папку» (файли замінюються).
3. Натисніть **Старт**. Кнопка **Скасувати** зупиняє роботу після поточного файлу (і під час пошуку файлів теж).
4. Наприкінці з'явиться підсумок: скільки оброблено, скільки зекономлено місця, які файли не вдалося обробити.

## Безпека ваших файлів

- Результат спочатку записується в тимчасовий файл, перевіряється і лише потім замінює оригінал.
  Якщо щось пішло не так - оригінал лишається недоторканим.
- Стиснення ніколи не збільшує файл: якщо результат виходить не меншим за оригінал - лишається оригінал.
- Пошкоджені (обрізані) файли не обробляються, а потрапляють у список помилок.
- Якщо файли змінюються на місці, наявні файли не перезаписуються: при зайнятому імені новий файл отримає суфікс `_1`.
  В окремій вихідній папці результати попереднього запуску просто оновлюються.
- Програма просить підтвердження, перш ніж замінювати файли на місці, видаляти EXIF без резервної копії
  або обходити цілий диск (наприклад, `C:\` разом з підпапками).
- Подробиці про помилки записуються в журнал: `%LOCALAPPDATA%\TechOfficeTool\TechOfficeTool.log`.

## Деталі по режимах

### 1. Конвертація .doc → .docx

- Word запускається один раз на всю пачку, невидимо; макроси в документах вимкнено.
- Документи з паролем не конвертуються - вони з'являться у списку помилок.
- Якщо поруч уже є `.docx` з такою ж назвою, файл **пропускається** (нічого не перезаписується і не дублюється).
- «Видаляти оригінальні .doc» відправляє `.doc` у **кошик** і лише після перевірки, що новий `.docx` справний.
- **Макроси.** Формат `.docx` не зберігає макросів. Якщо в `.doc` вони були, програма назве такі файли
  в підсумку і **не видалить** їхні оригінали, навіть якщо видалення увімкнено.
- «Без режиму сумісності» зберігає документ у найновішому форматі Word (зникає напис «Режим сумісності»).
  Верстка при цьому може трохи змінитись, тому за замовчуванням опцію вимкнено.

### 2. Стиснення зображень у .docx

- Обробляються картинки JPEG, PNG, GIF, BMP, TIFF. Прозорі PNG лишаються PNG, анімовані GIF не чіпаються.
- Якщо PNG вигідніше зберегти як JPEG - файл усередині документа отримує правильне розширення,
  а всі посилання на нього оновлюються.
- Програма враховує, **якого розміру картинка на сторінці**: маленьке фото не зберігатиме зайвих пікселів.
  Обрізані в Word фото та картинки, використані кілька разів, обробляються з запасом.
  Розмір картинки на сторінці й верстка не змінюються.
- Скріншоти й схеми, які в PNG займають менше, ніж у JPEG, не змінюються.
- Картинки у форматі CMYK (для друкарні) не чіпаються, щоб не зіпсувати кольори.
- Підпапки обробляються завжди.

### 3. Стиснення звичайних зображень

- Прозорість і колірні профілі (ICC) зберігаються. Анімовані GIF/WEBP, 16-бітні та CMYK-зображення не чіпаються.
- Якщо формат змінюється (наприклад, PNG → JPEG), змінюється і розширення файлу.
- Якщо двоє файлів претендують на одну назву (`фото.bmp` і `фото.jpg` → обидва `фото.jpg`), другий отримає `фото_1.jpg`.
- Повторний запуск у ту саму вихідну папку просто оновлює результати, без дублікатів.
- Без галочки «Зберігати EXIF» фото спершу повертаються за орієнтацією, а потім метадані видаляються.

### 4. Перейменування фото

- Шаблон назви: `{n}` - номер, `{name}` - стара назва, `{parent}` - назва папки, `{date}` - дата зйомки
  (або дата файлу), `{ext}` - розширення. Приклади: `IMG_{n:04d}` → `IMG_0001`, `{date}_{n}` → `2024-05-01_1`.
- Спершу увімкнено **«Тільки попередній перегляд»**: показує план і нічого не змінює.
  **Відмінити перейменування неможливо**, тому завжди дивіться план перед справжнім запуском.
- Повторний запуск не додає суфіксів `_1`.

### 5. Видалення EXIF

- Для JPEG метадані прибираються **без перекодування** - якість фото не змінюється.
  Тег орієнтації лишається (це не персональні дані), тож фото не перевертаються.
- «Повна переупаковка» прибирає абсолютно все, попередньо повернувши фото за орієнтацією (для JPEG - з невеликими втратами).
- Працює для JPEG, PNG, WEBP. GIF, BMP, TIFF і анімації пропускаються.
- Резервні копії `*.bak` лежать поруч і **містять оригінальні EXIF і GPS** - не передавайте їх разом із чистими фото.

### Про рівні стиснення

Кожен рівень задає якість JPEG і найбільший розмір зображення.
У `.docx` картинка додатково зменшується до вказаної щільності (ppi) відносно її розміру на сторінці.
Для звичайних зображень діє лише обмеження довшої сторони.

| Рівень | Щільність у .docx | Довша сторона, не більше | Якість JPEG | PNG → JPEG |
|--------|-------------------|--------------------------|-------------|------------|
| Максимальна якість (архів) | без обмеження | 4000 px | 95 | ні |
| Для друку | 220 ppi | 2400 px | 88 | так |
| Для екрану | 150 ppi | 1600 px | 82 | так |
| Сильне стиснення | 96 ppi | 1200 px | 75 | так |

## Збірка EXE

На Windows запустіть `build_exe.bat` - готовий файл з'явиться в `dist\TechOfficeTool.exe`.
`build_exe_debug.bat` збирає версію з вікном консолі, зручну для діагностики.

Автоматично через GitHub: **Releases → Draft a new release → Choose a tag** (наприклад, `v1.0.0`) **→ Publish**.
Через кілька хвилин exe з'явиться в цьому релізі.

## Для розробників

```bash
pip install -r requirements-dev.txt
python -m pytest
```

| Файл | Призначення |
|------|-------------|
| `techoffice_core.py` | Уся логіка без інтерфейсу; саме її перевіряють тести |
| `DocxImageCompressor.py` | Вікно програми (tkinter), точка входу |
| `tests/` | Тести. Word і tkinter підміняються заглушками, тож тести працюють і без Windows |

Реальну конвертацію через Word і вигляд вікна після змін варто перевіряти вручну на Windows.
