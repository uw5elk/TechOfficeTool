# TechOfficeTool (UW5ELK)

Програма для Windows з графічним інтерфейсом для роботи з документами Word та зображеннями.

## Режими

| # | Режим | Що робить |
|---|-------|-----------|
| 1 | **Конвертувати .doc → .docx** | Пакетна конвертація старих документів. Потрібен Microsoft Word. |
| 2 | **Стиснути зображення в .docx** | Зменшує розмір документів, стискаючи картинки всередині. |
| 3 | **Стиснути звичайні зображення** | Пакетна обробка JPG, PNG, GIF, BMP, TIFF, WEBP. |
| 4 | **Перейменувати фото** | За шаблоном, з сортуванням за іменем/датою, попереднім переглядом і відміною. |
| 5 | **Видалити EXIF** | Очищення метаданих (GPS, камера, коментарі, XMP/IPTC). |

## Як запустити

**Варіант 1: готовий EXE.** Завантажте `TechOfficeTool.exe` з розділу Releases (або зберіть самі, див. нижче).

**Варіант 2: через Python.**
1. Встановіть Python 3.9 або новіший (з галочкою «Add to PATH»).
2. Запустіть `setup_install.bat` - він встановить залежності з `requirements.txt` і створить ярлик на робочому столі.
   Або вручну: `pip install -r requirements.txt`, потім `Start_Compressor.bat`.

## Гарантії безпеки даних

- Файл-результат спочатку пишеться у тимчасовий файл, перевіряється і лише потім **атомарно** замінює оригінал.
  Якщо щось пішло не так - оригінал лишається недоторканим.
- Якщо «стиснений» файл не менший за оригінал (і розміри не зменшувались), лишається оригінал.
- Якщо під час роботи закрити вікно або натиснути «Скасувати», програма доробить поточний файл і зупиниться.
- Усі помилки записуються в журнал: `%LOCALAPPDATA%\TechOfficeTool\TechOfficeTool.log`.
- Перед заміною файлів «на місці» і перед видаленням EXIF без резервної копії програма просить підтвердження.

## Деталі по режимах

**Конвертація .doc → .docx.** Один екземпляр Word на всю пачку; файли відкриваються лише для читання, макроси вимкнено.
Документ із паролем не конвертується (буде в списку помилок). Результат перевіряється перед тим, як з'явитись у папці.
Опція «Видаляти оригінали» відправляє .doc у **кошик** (якщо встановлено `send2trash`) і лише після перевірки нового .docx.

**Стиснення в .docx.** Обробляються зображення JPEG/PNG/GIF/BMP/TIFF. Прозорі PNG лишаються PNG, анімовані GIF не чіпаються.
Якщо PNG стає JPEG, файл отримує правильне розширення, а посилання в документі оновлюються.
Скріншоти й схеми, які в PNG займають менше, ніж у JPEG, не змінюються. Теги орієнтації фото зберігаються.
Рівні стиснення обмежують розмір зображення **в пікселях** (довша сторона), а не «ppi» - цифри в назвах рівнів орієнтовні.
Підпапки обробляються завжди.

**Стиснення зображень.** Прозорість і ICC-профілі зберігаються. Анімовані GIF/WEBP та 16-бітні зображення не чіпаються.
Із «Зберігати EXIF» вимкненим фото повертаються за орієнтацією, а потім метадані видаляються.

**Перейменування.** Шаблон: `{n}`, `{name}`, `{parent}`, `{date}`, `{ext}` (наприклад `IMG_{n:04d}`).
Спершу працює «Тільки попередній перегляд». Після реального перейменування в папці створюється файл `.rename_log_*.json`;
кнопка «Відмінити перейменування…» повертає старі назви. Повторний запуск не додає суфіксів `_1`.

**Видалення EXIF.** Для JPEG метадані прибираються **без перекодування** (піксели не змінюються); тег орієнтації лишається,
бо це не персональні дані. Режим «Повна переупаковка» прибирає все, повернувши пікселі за орієнтацією (з втратами для JPEG).
Працює для JPEG, PNG, WEBP; GIF, BMP, TIFF та анімації пропускаються.
Резервні копії `*.bak` лежать поруч і **містять оригінальний EXIF/GPS** - не передавайте їх разом із чистими фото.

## Збірка EXE

`build_exe.bat` створює `dist\TechOfficeTool.exe`. `build_exe_debug.bat` - консольну версію для діагностики.
Якщо поставити в GitHub тег `v*`, workflow `CI` сам збере exe й додасть його до релізу.

## Розробка

```bash
pip install -r requirements-dev.txt
python -m pytest
```

- `techoffice_core.py` - вся логіка без GUI (її й тестують);
- `DocxImageCompressor.py` - вікно (tkinter);
- `tests/` - тести. Word підміняється заглушкою, тож вони працюють і без Windows.
  Реальну COM-конвертацію у Word та вигляд вікна перевіряйте вручну.
